# ZoneLinks

Небольшой сайт-каталог для Minecraft в духе Modrinth: здесь можно выложить свои **моды** и **ресурспаки**, пока их проверяют на больших площадках (скоро добавятся и **плагины**). Сайт статический: без сервера, без базы данных и без сборки, поэтому его можно бесплатно разместить на **GitHub Pages**.

**Что умеет**

- Поиск по названию, автору и описанию. Фильтров по категориям нет, категории только показываются на карточках.
- Разделы «Моды» и «Ресурспаки». «Плагины» пока помечены как «скоро» и включаются одной строкой в настройках.
- Страница проекта: описание в Markdown, галерея, список изменений, все версии с фильтрами, блок совместимости, зависимости и ссылки.
- Окно скачивания в стиле Modrinth. Выбираешь версию игры и платформу, а сайт сам подбирает подходящий файл: релиз предпочитается бете и альфе, показываются нужные зависимости и подсказка по установке.
- Плашки «На проверке» и «Опубликован». Когда мод одобрят, на странице появится кнопка, ведущая на его официальную страницу.
- Тёмная и светлая тема, адаптивная вёрстка для телефона.

## 1. Как выложить сайт на GitHub Pages

Папка уже подготовлена как git-репозиторий: ветка `main`, первый коммит, `.gitignore`, `.gitattributes` и `.nojekyll` на месте. Осталось отправить её на GitHub и включить Pages.

### Шаг 1. Создай пустой репозиторий на GitHub

На github.com нажми **New repository**:
- **Repository name** — например `zonelinks`. Если назвать `<твой-ник>.github.io`, сайт будет открываться прямо по `https://<твой-ник>.github.io/`, без хвоста.
- **Public** — на бесплатном тарифе GitHub Pages работает только для публичных репозиториев.
- **Не ставь** галочки «Add a README», «.gitignore» и «license»: всё это уже есть в папке, иначе будет конфликт при первой отправке.

### Шаг 2. Отправь папку — выбери любой способ

**Вариант А — GitHub Desktop (проще всего, без команд).**
Установи [GitHub Desktop](https://desktop.github.com), войди в аккаунт → **File → Add local repository…** → выбери эту папку → **Publish repository**. Сними галочку «Keep this code private», иначе Pages не заработает бесплатно.

**Вариант Б — командная строка.** В папке сайта выполни:

```bash
git remote add origin https://github.com/<твой-ник>/<репозиторий>.git
```

```bash
git push -u origin main
```

При первой отправке Git откроет окно входа в GitHub — войди в браузере.

**Вариант В — через сайт GitHub.** В новом репозитории нажми **uploading an existing file**, перетащи **всё содержимое** папки (не саму папку) и нажми **Commit changes**. Скрытая папка `.git` не нужна — её перетаскивать не надо.

### Шаг 3. Включи GitHub Pages

В репозитории: **Settings → Pages** → *Build and deployment* →
**Source:** `Deploy from a branch`, **Branch:** `main`, папка **`/ (root)`** → **Save**.

Через 1–2 минуты сайт откроется по адресу `https://<твой-ник>.github.io/<репозиторий>/`. После каждого изменения файлов GitHub сам пересобирает сайт, обычно за минуту.

### Как потом обновлять сайт

- **GitHub Desktop:** поменял файлы → в программе появятся изменения → впиши описание → **Commit to main** → **Push origin**.
- **Командная строка:**

```bash
git add .
```

```bash
git commit -m "Новая версия мода"
```

```bash
git push
```

> Файл `.nojekyll` в корне нужен: он отключает обработку Jekyll, и сайт публикуется быстрее и без сюрпризов. Не удаляй его.

**Ограничения GitHub для файлов модов**

| Размер файла | Как загрузить |
|---|---|
| до 25 МБ | через сайт GitHub (Upload files) в папку `files/` |
| 25–100 МБ | только через `git push` |
| больше 100 МБ | только в **Releases** репозитория (до 2 ГБ), в `url` указывается ссылка на файл релиза |

Ссылка на файл из релиза выглядит так:
`https://github.com/<ник>/<репозиторий>/releases/download/<тег>/<имя-файла>.jar`

## 2. Как посмотреть сайт у себя на компьютере

Можно просто открыть `index.html` двойным щелчком, сайт работает и без сервера.
Если хочешь, чтобы всё было точно как на GitHub Pages, запусти в папке сайта:

```bash
python -m http.server 8000
```

и открой `http://localhost:8000`.

## 3. Из чего состоит сайт

```
index.html              — единственная HTML-страница (всё остальное рисует JavaScript)
.nojekyll               — отключает Jekyll на GitHub Pages
data/
  projects.js           — КАТАЛОГ: здесь описаны все моды, ресурспаки и плагины
files/
  <slug>/               — файлы проектов: .jar, .zip, иконки, скриншоты
  demo/                 — файлы демо-проектов (удали вместе с демо)
assets/
  css/style.css         — оформление и палитра
  img/logo.svg          — логотип (он же иконка вкладки)
  js/config.js          — НАСТРОЙКИ: название, тексты на главной, ссылки, плагины
  js/catalog.js         — справочник категорий и платформ
  js/markdown.js        — отображение описаний в формате Markdown
  js/app.js             — логика сайта
figma-plugin/           — плагин для Figma, который строит макет сайта (для работы сайта не нужен)
```

Адреса страниц выглядят так: `#/mods`, `#/resourcepacks`, `#/mod/<slug>`, `#/mod/<slug>/versions`.
Решётка в адресе нужна, чтобы все ссылки работали на GitHub Pages без дополнительных настроек.

## 4. Как добавить проект

### Шаг 1. Загрузи файл

Положи `.jar` или `.zip` в папку `files/<slug>/`, где `<slug>` — короткое имя проекта латиницей через дефисы, например `files/ember-lanterns/ember-lanterns-1.2.0-fabric.jar`.
Если файл большой, загрузи его в **Releases** и используй ссылку (см. таблицу выше).

Иконку (квадратную, от 128×128) и скриншоты тоже удобно класть в эту папку: `files/<slug>/icon.png` и `files/<slug>/gallery/1.png`.

### Шаг 2. Опиши проект в `data/projects.js`

Добавь в массив `window.PROJECTS` новый объект. Его удобно не писать руками, а получить у ИИ по анкете (см. [раздел 8](#8--промт-для-ии-и-анкеты)). Минимальный пример:

```js
{
  slug: 'ember-lanterns',
  type: 'mod',
  title: 'Ember Lanterns',
  author: 'МойНик',
  summary: 'Янтарные фонари шестнадцати цветов.',
  categories: ['decoration'],
  environment: { client: 'required', server: 'required' },
  description: `
Тёплые **янтарные фонари** для уютных построек.

## Возможности
- 16 цветов
- Мягкое мерцание
`,
  versions: [
    {
      name: 'Ember Lanterns 1.2.0',
      number: '1.2.0',
      channel: 'release',
      date: '2026-09-24',
      gameVersions: ['1.21.1', '1.21'],
      loaders: ['fabric'],
      changelog: '- Добавлены цепи',
      files: [
        { name: 'ember-lanterns-1.2.0-fabric.jar', url: 'files/ember-lanterns/ember-lanterns-1.2.0-fabric.jar' }
      ]
    }
  ]
},
```

> ⚠️ Между объектами в массиве ставятся **запятые**. Текст описания пишется в обратных кавычках `` ` ``: если внутри описания нужна обратная кавычка, пиши `` \` ``, а вместо `${` пиши `\${`.

### Шаг 3. Удали демо

В `data/projects.js` лежат три демо-проекта с полем `demo: true`. Удали их и папку `files/demo`.

### Новая версия

Добавь ещё один объект в `versions` этого проекта. Порядок значения не имеет: версии сортируются по дате автоматически.
Если под разные платформы у тебя разные файлы (отдельные для Fabric и NeoForge), делай **отдельный объект версии на каждую платформу** с одинаковым `number`.

### Когда проект одобрили

Поставь `status: 'released'` и добавь ссылку в `links.modrinth` (или `links.curseforge`). На странице появится зелёная плашка «Проект прошёл проверку» с кнопкой на официальную страницу.

## 5. Все поля проекта

| Поле | Обязательно | Что это |
|---|---|---|
| `slug` | да | Короткое имя латиницей: `ember-lanterns`. Используется в адресе страницы. |
| `type` | да | `'mod'`, `'resourcepack'` или `'plugin'`. |
| `title` | да | Название. |
| `summary` | да | Одно предложение для карточки. |
| `author` / `authorUrl` | нет | Ник автора и ссылка на профиль. |
| `icon` | нет | Путь к иконке. Если не указать, сгенерируется цветная иконка с буквами. |
| `categories` | да | Список ID категорий (см. [раздел 6](#6-категории-и-платформы)). Только для показа. |
| `status` | нет | `'review'` — на проверке (по умолчанию), `'released'` — уже опубликован, `'none'` — без плашки. |
| `license` / `licenseUrl` | нет | Лицензия и ссылка на её текст. |
| `environment` | нет | `{ client, server }`, значения: `'required'`, `'optional'`, `'unsupported'`. Для ресурспаков не нужно. |
| `published` / `updated` | нет | Даты `'ГГГГ-ММ-ДД'`. Если не указать, возьмутся из дат версий. |
| `links` | нет | `{ modrinth, curseforge, source, issues, wiki, discord, website }`, только нужные. |
| `dependencies` | нет | `[{ title, url, required, loaders }]`. `loaders` — если зависимость нужна только на одной платформе. |
| `gallery` | нет | `[{ url, title, description }]`. |
| `description` | нет | Описание в Markdown. |
| `downloads` | нет | Число скачиваний, если хочешь показать его вручную (сам сайт скачивания не считает). |
| `versions` | да | Список версий, см. ниже. |

**Поля версии**

| Поле | Что это |
|---|---|
| `name` | Название версии: `'Ember Lanterns 1.2.0'`. |
| `number` | Номер: `'1.2.0'`. |
| `channel` | `'release'`, `'beta'` или `'alpha'`. |
| `date` | Дата выхода `'ГГГГ-ММ-ДД'`. |
| `gameVersions` | Версии Minecraft: `['1.21.1', '1.21']`. |
| `loaders` | Платформы: `['fabric']`. У ресурспаков не нужно. |
| `changelog` | Что нового (Markdown). |
| `files` | `[{ name, url, size, primary }]`. `size` — в байтах (необязательно), `primary: true` — основной файл (по умолчанию первый). |

**Markdown в описании:** заголовки `##`, **жирный** `**текст**`, *курсив* `*текст*`, списки `- пункт`, ссылки `[текст](https://...)`, картинки `![](files/slug/1.png)`, таблицы, цитаты `>`, код в обратных кавычках. HTML не поддерживается и показывается как текст (это защита).

## 7. Настройка: название, цвета, логотип, плагины

- **Название, тексты на главной, ссылки на GitHub и Discord** находятся в `assets/js/config.js`.
- **Палитра** задаётся в начале `assets/css/style.css`, в блоке «Палитра». Главные цвета — `--accent` (морской синий: кнопки, ссылки) и `--accent-2` (глубже, при наведении); их меняют в обеих темах, тёмной и светлой. Градиентов на сайте нет — только сплошные цвета.
- **Логотип** — файл `assets/img/logo.svg`. Замени его своим SVG с тем же именем, и он обновится и в шапке, и во вкладке браузера.
- **Плагины**: в `config.js` поставь `pluginsEnabled: true`, и раздел заработает так же, как «Моды».

## 8. 🤖 Промт для ИИ и анкеты

### Как пользоваться

1. Скопируй **промт** ниже целиком и отправь ИИ (ChatGPT, Claude и т. п.) первым сообщением.
2. Затем отправляй заполненные **анкеты** (шаблоны ниже, после промта).
3. ИИ ответит: какой это тип проекта, какие категории он выбрал и почему, готовый объект для `data/projects.js`, куда положить файлы и чего не хватает.
4. Вставь объект в массив `window.PROJECTS`, положи файлы в указанные папки и загрузи всё на GitHub.

### Промт

````text
Ты — редактор каталога «ZoneLinks». Это статический сайт на GitHub Pages, где я временно выкладываю свои проекты для Minecraft: Java Edition, пока их проверяют на Modrinth/CurseForge. Все проекты описаны в файле data/projects.js — это JavaScript-массив window.PROJECTS.

Я буду присылать АНКЕТЫ: мода, ресурспака, плагина или обновления. По каждой анкете выполни шаги 1–4.

━━━━━━━━ ШАГ 1. ТИП ПРОЕКТА (поле type) ━━━━━━━━
• "mod" — файл .jar, который загружает загрузчик модов (Fabric, Forge, NeoForge, Quilt); кладётся в .minecraft/mods или в mods на сервере с загрузчиком. Признаки: fabric.mod.json, mods.toml, neoforge.mods.toml, quilt.mod.json, миксины, новые блоки/предметы/мобы/механики через код.
• "resourcepack" — архив .zip с pack.mcmeta; кладётся в .minecraft/resourcepacks. Меняет только ресурсы: текстуры, модели, звуки, музыку, шрифты, язык, интерфейс, core-шейдеры. Кода нет.
• "plugin" — файл .jar для серверного ядра (Paper, Spigot, Bukkit, Purpur, Folia, Sponge) или прокси (Velocity, BungeeCord, Waterfall); кладётся в папку plugins сервера. Признаки: plugin.yml, paper-plugin.yml, velocity-plugin.json, bungee.yml. Игрокам ничего ставить не нужно.

Спорные случаи:
• Серверный мод на Fabric/NeoForge (ставится только на сервер, но через загрузчик модов) — это "mod", а не "plugin".
• Ресурспак, которому нужен мод (OptiFine, CIT Resewn, EMF/ETF и т. п.), — всё равно "resourcepack": добавь категорию "modded" и укажи мод в dependencies.
• Шейдерпак (Iris/OptiFine), датапак, модпак, карта, скин — сайт такое не поддерживает. Скажи об этом и НЕ создавай объект.
• Если по анкете тип понять нельзя — задай ОДИН уточняющий вопрос и остановись.

━━━━━━━━ ШАГ 2. КАТЕГОРИИ (поле categories) ━━━━━━━━
Правила:
1. Только ID из списков ниже — латиницей, ровно как написано.
2. Мод/плагин: от 1 до 3 категорий. ПЕРВАЯ — главная: то, ради чего проект скачивают. Остальные — только если это заметная часть проекта, а не мелочь.
3. Ресурспак: от 1 до 3 категорий из групп «Стиль» и «Что меняет» + РОВНО ОДНА категория разрешения, последней в списке. Если пак меняет только звуки или только перевод — разрешение не ставь. Если разрешение не указано, а пак с текстурами — поставь 16x и напиши об этом в «Чего не хватает».
4. Опирайся на то, что проект ДЕЛАЕТ, а не на название и рекламные слова из описания.
5. library — только если проект сам по себе игроку почти ничего не даёт и нужен другим модам/плагинам. Обычно это единственная категория.
6. optimization — только если главная цель — FPS, TPS, память или скорость загрузки.
7. cursed — только для откровенно шуточных/абсурдных проектов или если автор сам так пишет.
8. Не ставь utility «на всякий случай», если подходит что-то конкретнее.

Категории МОДОВ и ПЛАГИНОВ:
- adventure — данжи, боссы, квесты, исследование мира, измерения с целью «пройти»
- cursed — шуточное, абсурдное, мемное, «сломанное нарочно»

━━━━━━━━ ШАГ 3. ОСТАЛЬНЫЕ ПОЛЯ ━━━━━━━━
• slug — из названия: латиница в нижнем регистре, цифры и дефисы. Кириллицу транслитерируй. «Ember Lanterns» → "ember-lanterns", «Мягкий камень» → "myagkiy-kamen".
• loaders (в каждой версии):
  – мод: fabric, forge, neoforge, quilt — только заявленные в анкете (quilt — только если автор подтвердил совместимость);
  – плагин: paper, purpur, spigot, bukkit, folia, sponge, velocity, bungeecord, waterfall. Совместимость по цепочке Bukkit → Spigot → Paper → Purpur: плагин для Bukkit работает на Spigot, Paper и Purpur; для Spigot — на Paper и Purpur; для Paper — на Purpur. Folia — только если автор явно заявил;
  – ресурспак: loaders не пиши.
• gameVersions — все версии Minecraft явным списком, от новой к старой: ["1.21.1", "1.21"]. Диапазон «1.20–1.20.4» раскрой в реально существующие релизы: ["1.20.4", "1.20.3", "1.20.2", "1.20.1", "1.20"].
• environment — только для mod и plugin, значения "required" | "optional" | "unsupported":
  – чисто клиентский мод (HUD, миникарта, оптимизация рендера): { client: "required", server: "unsupported" }
  – мод с новыми блоками/предметами/мобами: { client: "required", server: "required" }
  – серверный мод: { client: "unsupported", server: "required" } (client "optional", если с ним на клиенте удобнее)
  – плагин: { client: "unsupported", server: "required" }
• channel — "release" по умолчанию; "beta", если в номере есть beta, b1, pre, rc; "alpha", если alpha, a1, snapshot, dev, experimental.
• versions — один объект на каждый набор файлов. Если под разные платформы разные файлы (отдельные .jar для Fabric и NeoForge) — отдельный объект на каждую платформу с одинаковым number.
• files — url: "files/<slug>/<имя файла>", если файл лежит в репозитории, или прямая ссылка из анкеты (например, GitHub Releases). size — в байтах, только если известен.
• даты — формат "ГГГГ-ММ-ДД". Нет даты — поставь сегодняшнюю и отметь это в «Чего не хватает».
• status — "review" по умолчанию; "released", если в анкете есть ссылка на уже одобренную страницу (её — в links.modrinth или links.curseforge).
• links — только заполненные из: modrinth, curseforge, source, issues, wiki, discord, website.
• dependencies — [{ title, url, required: true|false, loaders: [...] }]. loaders — только если зависимость нужна на одной платформе (Fabric API → ["fabric"]).
• summary — одно предложение до 120 символов, без рекламы.
• description — Markdown по-русски в обратных кавычках: вступление в 1–2 предложения, «## Возможности» списком, «## Установка»; при необходимости «## Совместимость», для плагинов — «## Команды» и «## Права». Не придумывай того, чего нет в анкете. Внутри текста обратную кавычку пиши как \` , а ${ — как \${ .
• icon, gallery — пути "files/<slug>/icon.png", "files/<slug>/gallery/1.png" или ссылки из анкеты. Нет данных — не пиши поле.
• НЕ добавляй поля demo и downloads. НЕ выдумывай ссылки, лицензию, версии, размеры и даты.
````

## 9. Если что-то не работает

- **Страница пустая или проект не появился.** Скорее всего, ошибка в `data/projects.js`: пропущена запятая между объектами, не закрыта кавычка или внутри описания стоит обратная кавычка без `\`. Открой сайт, нажми **F12 → Console**: там будет строка с ошибкой. Сайт также пишет в консоль предупреждения о неизвестных категориях, типах и повторяющихся `slug`.
- **Файл не скачивается (404).** Проверь, что путь в `url` точно совпадает с путём в репозитории, включая регистр букв: GitHub различает `Mod.jar` и `mod.jar`.
- **Изменения не видны.** GitHub Pages обновляется 1–2 минуты. Потом обнови страницу с очисткой кэша: **Ctrl+F5**.
- **Сайт открылся без стилей.** Нужно загружать *содержимое* папки в корень репозитория, а не саму папку целиком.
